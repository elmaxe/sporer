# Spore 2: space stage

Browser game in Three.js inspired by Spore's space stage. Stack: Vite + TypeScript (strict), three, Rapier (`@dimforge/rapier3d-compat`), lil-gui + stats.js (debug), Vitest.

## Commands

- `npm run dev`: dev server on http://localhost:5173 (debug panel on)
- `npm run typecheck` / `npm test` / `npm run build` / `npm run preview`
- `npm run smoke`: headless browser check (needs the dev server running): loads the game, checks the ship hovers above the star with no manual flying, checks the system map, the stars and comets are alive, hovers and clicks an asteroid belt, runs the galaxy and planet loops, enters a system inside each kind of nebula, flies to a rogue planet and down to it, finds a black hole on the galaxy map and flies into its system (its shadow black, its disc lit, a planet under it), visits a young star's disc and a forming planet, a debris disc and the home system's meteor showers and impact flashes (every planet type, geyser kind and weather kind, `-- --quick` for just the home system; every zoom between levels must crossfade and never go black), grows every plant architecture at every level of detail in the plant lab, grows and walks every animal body plan in the animal lab and finds a herd roaming the home planet and tracks it with the radar (the Inventory's Radar switch, the species picked on the planet map's Species tab), draws every kind of star and tunes a system in the star lab, plays with touch on an emulated phone (the release notes scroll with a swipe), beams plants and animals up into the hold and sets them down again, kills an animal and a tree with the laser, raises a volcano with the volcano bomb, fires the planet buster at a moon (last); in every planet loop also checks the geysers' sound, the rocks loaded near the ground and the ship's downwash over water and lava; reports FPS and console errors plus screenshots. `-- --only <sections>` runs just some (`core,galaxy,nebulas,rogues,blackholes,dust,audio,planet,types,lab,plants,animals,stars,touch,cargo,volcano,buster`; use this while working, the full run before pushing); it renders at `?quality=low` unless `--full-quality`, prints each section's time as it goes, and fails fast (naming the step) if the page stalls
- `npm run offline`: builds, then checks the service worker (`src/pwa/sw.ts`, compiled to `sw.js` by the plugin in `vite.config.ts`; only production builds have one) in a headless browser: the build served like the Pages site (release and preview), the game, the planet lab and the preview start with the server stopped, and the menu's Refresh button brings in a new version (`-- --no-build` checks the `dist/` that's there)
- `npm run shot -- --out <dir> --clean <steps...>`: screenshots of the running game after scripted steps (see the `screenshot` skill); `--lab` shoots the planet lab instead, `--plants` the plant lab, `--animals` the animal lab, `--stars` the star lab
- `npm run dump -- <file.json>`: unpacks a debug dump (the game menu's Save debug dump button, or F8; in the planet and plant labs the readout's Report button, or F8: the screen, the player's marks and note, game state (in a lab: the exact planet or plants, view and camera), device, GPU, frame times, console errors, in one JSON file) into pictures and a summary; `npm run shot -- --dump <file.json>` restores its state in the headless browser (see the `debug-dump` skill). Dumps attached to issues are copied to the `debug-dumps` branch as `issue-<n>/<file>.json` by the `Issue dumps` workflow, since cloud sessions can't download issue attachments
- Planet lab: http://localhost:5173/lab.html (deployed at https://elmaxe.github.io/sporer/lab.html). One planet or moon drawn by the game's own code, every property editable in the panel (type, size, colours, sea, relief, craters, gas bands, atmosphere, climate and the weather it brings, rings, moons, a comet's or asteroid's shape, a comet's activity, light, time), in low orbit or the system view. Use it to look at, debug and test planet features: `?gen=<seed>&type=<type>&kind=<size class, moon, comet or asteroid>` makes one, `?seed=<galaxy>&star=<id>&planet=<i>[&moon=<j>]` loads a game planet (`&comet=<k>` instead of `planet` a comet, `&belt=<b>&asteroid=<k>` a named asteroid), the `#hash` is the exact planet (the page keeps it updated; the game's menu (Esc, or the menu button on phones) and low orbit's debug panel open the current planet in it; it works on phones too), and `window.lab` drives it (`lab.set`, `generate`, `load`, `loadComet`, `loadAsteroid`, `look`, `lookAtVent`, `lookAtStorm`, `setTime`, `ready`)
- Plant lab: http://localhost:5173/plants.html (deployed at https://elmaxe.github.io/sporer/plants.html). Plant species grown by the game's own generator (`gen/plantForm.ts`: conifers, broadleaves, palms, shrubs) and drawn with its own meshes and materials (`surface/plantMesh.ts`, `plantLook.ts`). Every species property is editable in the panel: envelope, branching, leaves, colours. Views: one plant (zoom out through the game's level-of-detail crossfade), the levels side by side, or a grove planted by the game's `SurfaceEntities` on a whole green planet (zoom out to the globe and drag to turn it, WASD to move over it); the levels can be tinted. `?gen=<seed>&tier=<1-3>&kind=<kind>&arch=<architecture>` makes a set, `?seed=<galaxy>&star=<id>&planet=<i>[&species=<j>]` loads a game planet's plants, and the `#hash` is the exact set. The planet lab's Plants link opens its planet's species. `window.plantLab` drives it (`set`, `setForm`, `select`, `setArchitecture`, `generate`, `load`, `setView`, `look`, `ready`)
- Animal lab: http://localhost:5173/animals.html (deployed at https://elmaxe.github.io/sporer/animals.html). Animal species generated by the game's own code (`gen/animalForm.ts`: four-legged, six-legged and two-legged bodies round a spine; `gen/animals.ts`: a planet's species by tier, herds whose walks are pure functions of the clock, gaits by dynamic similarity) and drawn and walked with its own meshes and shader (`surface/animalMesh.ts`, `animalLook.ts`). Animals live wherever plants grow, so a world terraformed into a habitable tier gains them. Every property is editable in the panel: size, diet, herd, proportions, features, coat, plus the gravity the gait is worked out for. Views: one animal (standing, grazing, or walking or trotting round a circle; zoom out through the levels of detail), its levels side by side, the whole set side by side, or herds roaming a whole green planet with the game's `SurfaceAnimals` and plants. `?gen=<seed>&tier=<1-3>&diet=<diet>&plan=<body plan>&pace=<stand|graze|walk|trot>` makes a set, `?seed=<galaxy>&star=<id>&planet=<i>[&species=<j>]` loads a game planet's animals, and the `#hash` is the exact set. The planet lab's Animals link opens its planet's species. `window.animalLab` drives it (`set`, `setForm`, `select`, `setBodyPlan`, `reroll`, `generate`, `load`, `setView`, `look`, `lookAtHerd`, `ready`)
- Star lab: http://localhost:5173/stars.html (deployed at https://elmaxe.github.io/sporer/stars.html). A star or a black hole (`gen/blackHoles.ts`: its mass, its accretion disc's reach and feeding, drawn by `world/BlackHoleLook.ts`), or a binary pair, and the system it grows, drawn by the game's own code (`StarSystem`: surfaces, coronas, storms, planets, belts, comets, dust). Every star property is editable in the panel: kind, class, colour, radius, luminosity, mass, a companion, youth, and how it lives (`gen/starActivity.ts`: surface pace, granulation, spots, rotation, corona pulse, prominences and flares), kept on the star as `StarData.activity`. Dice for a new star, another look (colour and behaviour round its kind's) and another system round it, and the system tuner (`gen/system.ts` `tuneSystem` / `SystemTuning`: planets, spacing, moons each, comets, main belt, debris disc; `{}` is exactly the game's system). Views: the star(s) close up, or the whole system (hover for names, click a body to follow it); time speed. `?gen=<seed>&kind=<kind>&class=<class>&binary=0|1&young=1` makes one, `?seed=<galaxy>&star=<id or sol>` loads a game system, and the `#hash` is the exact state. The game's menu opens the current system in it, the planet lab's Star link its planet's system, and each planet in its readout opens in the planet lab. `window.starLab` drives it (`setStar`, `setActivity`, `setTuning`, `setBinary`, `setYoung`, `rerollLook`, `rerollSystem`, `generate`, `load`, `setView`, `focus`, `look`, `setTime`, `ready`)
- Creature editor (prototype): http://localhost:5173/creature.html. Spore's creature creator on the animal lab's body: drag the spine's vertebrae and fatten them with the wheel, stick parts (legs, arms, eyes, horns, ears, spikes, antennae) anywhere on the skin, paint the coat and brush strokes, and watch it walk with feet planted by IK in a gait worked out from where its legs are (`gen/creature.ts`, `gen/creatureMotion.ts`, `src/creaturelab/`; approach and sources in `docs/research/creature-editor.md`). The `#hash` is the design. `window.creatureLab` drives it (`setDesign`, `setMode`, `look`, `startPlacing`, `dabAtScreen`, `undo`, `ready`), `window.creatureKit` makes designs (`blob`, `random(seed)`, `animal(seed, plan)`); `npm run shot -- --creatures` shoots it
- Spaceship editor (prototype): http://localhost:5173/ship.html. Spore's spaceship creator: a core hull and parts (bodies, cockpits, wings, engines, guns, lights, antennae, dishes, grabbers) stuck onto each other's surfaces, mirrored and/or copied round the ship, a complexity meter, a wireframe view (X), paint (colours, finish, hull pattern, a bucket for single parts) and a test flight over a planet; its 🚀 Fly in the game keeps the ship in local storage and the game flies it instead of the saucer (`player/customShip.ts`, drawn by `player/shipMesh.ts` `buildDesignedUfo` at the saucer's size; `?ship=<design>` in the game's address flies one for that visit; the game menu links the editor) (`gen/ship.ts`, `src/shiplab/`; approach and sources in `docs/research/spaceship-editor.md`). The `#hash` is the design. `window.shipLab` drives it (`setDesign`, `setMode`, `look`, `select`, `startPlacing`, `placeAtScreen`, `paintAtScreen`, `turnSelection`, `undo`, `ready`), `window.shipKit` makes designs (`saucer`, `random(seed)`); `npm run shot -- --ships` shoots it
- Deploy: GitHub Actions (`.github/workflows/deploy.yml`) runs typecheck/test/build and publishes each version to its own folder of GitHub Pages (kept on the `gh-pages` branch by `scripts/pages-publish.sh`, listed in its `versions.json`): a `v*` tag (a GitHub Release) to https://elmaxe.github.io/sporer/, `main` to https://elmaxe.github.io/sporer/preview/, each open pull request to https://elmaxe.github.io/sporer/pr/<n>/ (linked from a comment on it, removed when it's closed). The game menu's Version picker switches between them (`src/ui/versions.ts`), and an installed app opens the one picked. The root's `releases.json` holds the GitHub Releases' notes (refreshed at every publish, and by the workflow's `notes` job when a release is published, edited or deleted) for the menu's What's new (`src/ui/releaseNotes.ts`, `ReleaseNotesDialog.ts`; outside the Pages site it asks GitHub's API), and a release played for the first time says "Updated to …" at the top
- URL params: `?seed=<number or text>` picks the galaxy (default 1337), `?star=<id>` starts in that system (black holes, ~1 in 1000 systems: `galaxy.stars.filter((s) => s.stars[0].kind === 'blackHole')`, e.g. 818 in the default galaxy) (ids after the stars' are the rogue planets; `?star=sol` is our own solar system, in every galaxy; default: generated home system; the URL follows you as you change systems), `?debug` enables the debug panel in production builds, `?quality=low` renders at half resolution without antialiasing (about 5× faster under software WebGL; the smoke test uses it)

## Skills

- `threejs-game-conventions`: architecture, Entity lifecycle, physics/perf rules. Read before writing game code.
- `run-game`: start the server and verify in Chrome. Use after changes.
- `screenshot`: take in-game screenshots with `npm run shot` whenever something needs checking by eye (the planet lab with `--lab`: the quickest way to see a planet feature on any kind of body; the plant lab with `--plants` for plants and their levels of detail; the animal lab with `--animals` for animals, their walk and herds; the star lab with `--stars` for stars and whole systems).
- `debug-dump`: read a debug dump file the player saved (sporer-dump-*.json) and reproduce it. Use whenever one is shared.
- `research`: researching anything real-world (climate, atmospheres, physics, techniques): look it up, measure it against reference cases, record it in `docs/research/`. Never guess numbers.

## Issues

When asked to fix an issue, first mark it In Progress on the project (https://github.com/users/elmaxe/projects/1): run the `Project status` workflow (`.github/workflows/project-status.yml`, on `main`) with the issue's number and the status `In Progress`, and check that the run succeeded. It adds the issue to the project if it isn't there yet. If it fails, say so and carry on with the fix.

## Pull requests

A pull request that fixes or changes something you can see (a debug dump's bug, a rendering or layout fix, a new visual) shows pictures of it in its description: before and after, side by side, taken with `npm run shot` (for a dump, `--dump` restores its moment). GitHub's API can't upload images, so push them to the `pr-pictures` branch (an orphan branch holding only pictures; create it with `git checkout --orphan pr-pictures` and `git rm -rf .` if it doesn't exist) under a folder named after the PR's branch, and link each one in the description as `![what it shows](https://raw.githubusercontent.com/elmaxe/sporer/pr-pictures/<branch>/<file>.png)`. Never commit them to the PR's own branch. Crop to the part that matters and keep each file small (a few hundred KB).
